# MoNaCo instruction 합의 선택: 추가 30문제와 50문제 합산

### 목적

[20문제 본 실행](2026-10-14-monaco-instruction-selection.ko.md)에서 사후에 본 두 결과(항상 clarify가 naive보다
+0.065, probe 정답 점수로 고르면 +0.084)를 새 문제에서 확인하고, 처음 20문제와 합친 50문제로 추정을 좁힌다.
탐색 실험이다.

### 설정

- `monaco-instruction-selection-v6`. v5와 다른 점은 목록 점수의 recall 상한(작은 버그 수정)뿐이라 v5 재채점 20문제와
  하나로 합친다([C40](../decisions.md)). 설계·모델·선택 규칙·judge(luna-high, 최종 답 줄만)는 v5 재채점과 같다.
- 문제: pool 540개에서 이미 쓰거나 점검한 126개(본 실행 20, 묶기 검증 100, 점검 805·1250·486·415·910·1707)를 뺀
  414개 중 seed 1로 30문제(단일 답 11, 목록 19). gold는 보지 않고 골랐다(`target_selection.json`).
- 후보 생성은 코드 검사(세 축, 180단어 이하, 서로 다름)만 하고 내용 검토는 없다(처음 20문제와 같다). 실행 후 gold 문자열
  대조로 정답 누출이 없음을 확인했다(4건 걸렸으나 "yes or no" 형식 언급과 "an actor" 예시).
- 실험 디렉터리 `outputs/experiments/2026-10-14_monaco-instruction-selection-extra30`, probe 채점
  `...-extra30-probe-judge`, 합산 `...-pooled50`(`scripts/analyze_monaco_pooled.py`, 호출 없음).

합계 $4.48, sync 동시 4. 오류·429·비용 불명 호출 없음.

judge 검증의 불일치 11개는 다음과 같다. 공개 GPT-4o 자유 서술 답 원문을 채점하는 검증이라 실제 실행 채점(`ANSWER:` 한 줄)
보다 어려운 조건이다. 30문제 평균으로 우리 judge가 0.014 높다.
- 자유 서술 본문 항목을 답으로 셈(1053, 1245): 실제 실행 채점에는 해당하지 않는다.
- 공개 채점의 숫자 계산 오류(559, 1700): 우리 judge가 공개 공식 `1 − |gold − pred| / max`대로 계산했다.
- 공개 채점이 같은 항목을 두 번 셈(999, "Meta Platforms"와 "Meta"): v6에서 고친 것과 같은 유형이다.
- 부분 일치 인정 범위(13, 101, 915, 1492, 1801은 우리가 높고 1757은 낮음): 판단 차이다.

### 결과: 새 30문제

| 정책 | 평균 | naive 대비 (CI) | random 대비 (CI) |
|---|---:|---:|---:|
| 합의 선택 (selected) | 0.702 | −0.010 (−0.043, 0.022) | +0.008 (−0.017, 0.033) |
| naive | 0.711 | – | +0.017 (0.004, 0.033) |
| analogical 고정 | 0.707 | −0.005 (−0.030, 0.022) | |
| clarify 고정 | 0.685 | −0.027 (−0.058, 0.003) | |
| local_check 고정 | 0.673 | −0.039 (−0.068, −0.013) | |
| random | 0.694 | −0.017 (−0.033, −0.004) | – |
| probe 점수로 고르기 (진단, gold 사용) | 0.720 | +0.008 (−0.004, 0.023) | |
| 사후 최고 | 0.739 | +0.027 (0.009, 0.049) | |

- **clarify는 재현되지 않았다.** 처음 20문제 +0.065 → 새 30문제 −0.027.
- **probe 점수로 고르기도 거의 재현되지 않았다.** +0.084 → +0.008. 처음 20문제의 +0.084는 두 문제(444 +0.71,
  1809 +0.67)가 대부분이었다.
- **headroom이 작다.** 사후 최고 − naive +0.027은 후보 구분 없이 섞은 기준선(`hindsight_null` 평균 +0.036,
  0.019–0.053)보다 작다. 30문제 중 16문제는 네 후보의 실행 점수가 모두 같다.
- **local_check는 naive보다 낮다.** 처음 20문제(−0.059)와 같은 방향이고 새 30문제에서 CI가 0을 넘지 않는다.
  local_check는 빈 probe 답이 가장 많다(새 30문제 34개, naive 16개).
- 동점: 단독 최고 14문제, 2개·4개 동점 4·12문제. 규칙 정규화 완전 일치 합의였다면 21문제에서 같은 후보를 골랐다.
- 빈 답 합의가 다시 나왔다. 1053("왕정 복고를 시도한 서유럽 공화국")에서 analogical·local_check의 probe 9개가 모두
  `[]`라 합의 1.0으로 analogical이 뽑혔다. 이 문제는 naive 실행도 0점이라 손해는 없었다.
- probe 채점 순서 일치(같음/반대/동점): 합의 vs probe 점수 39/44/97, probe 점수 vs 실행 55/13/112. 합의가 probe 정답을
  가리키지 못하는 점은 처음 20문제와 같다.

### 결과: 50문제 합산 (v5 재채점 20 + v6 30)

| 정책 | 평균 | naive 대비 (CI) | random 대비 (CI) |
|---|---:|---:|---:|
| 합의 선택 (selected) | 0.690 | −0.009 (−0.073, 0.048) | +0.002 (−0.034, 0.037) |
| naive | 0.699 | – | +0.011 (−0.014, 0.042) |
| analogical 고정 | 0.690 | −0.009 (−0.065, 0.036) | |
| clarify 고정 | 0.709 | +0.010 (−0.028, 0.059) | |
| local_check 고정 | 0.652 | −0.047 (−0.101, −0.008) | −0.036 (−0.065, −0.012) |
| random | 0.687 | −0.011 (−0.042, 0.014) | – |
| probe 점수로 고르기 (진단, gold 사용) | 0.737 | +0.039 (0.006, 0.083) | |
| 사후 최고 | 0.757 | +0.058 (0.021, 0.107) | |

- `hindsight_null` 평균 +0.045(0.024–0.070). 사후 최고 − naive +0.058의 대부분이 실행 3회의 잡음으로 설명된다.
- probe 점수로 고르기 +0.039는 선택(probe)과 평가(실행) 표본이 분리된 값이라 후보 간 실제 차이가 0은 아니다.
  다만 처음 20문제에서 본 크기(+0.084)의 절반 이하다.
- 합의 선택은 random 대비 +0.002(CI −0.034, 0.037)로, random보다 0.04 이상 낫다는 가능성은 낮다.
- 유형별: 목록 29문제에서 합의 선택 −0.054, local_check −0.086(naive 대비), 단일 21문제에서 합의 선택 +0.053.
  유형별은 사후에 나눈 것이다.
- 순서 일치(같음/반대/동점): 합의 vs probe 점수 67/77/156, probe 점수 vs 실행 92/32/176.
- 처음 20문제의 probe 점수에는 v6 recall 상한이 적용되지 않았다(2건, 영향 0.001). C40에 따라 다시 계산하지 않았다.

### 해석

- 이 설정(oracle 문서, haiku 실행)에서 문제별 instruction의 효과는 대부분 작다. 50문제에서 확인되는 것은
  local_check가 naive보다 낮다는 것뿐이고, 처음 20문제에서 본 clarify의 이득은 재현되지 않았다.
- 합의 선택은 50문제에서도 naive·random과 차이가 없다. 합의는 probe 답의 정답 여부를 가리키지 못하고(67 대 77),
  빈 답처럼 지시가 답을 좁혀 생기는 합의가 두 번(443, 1053) 나왔다.
- 후보 내용은 검토하지 않았으므로 결과는 "sonnet이 축 이름으로 쓴 문구"의 효과다.
