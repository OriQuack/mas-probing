# MoNaCo instruction 합의 선택: 20문제 본 실행

### 목적

LongCoT math에서 본 instruction 선택을 non-math 질의응답에서 확인한다. MoNaCo oracle 설정(질문 + gold 근거 문서)에서
문제마다 후보 instruction 4개 중 하나를 probe 답의 합의로 고르고, 사후 최고(`best_in_hindsight`) − naive로 잰
headroom을 합의 선택이 얼마나 되찾는지 본다. 탐색 실험이다.

### 설정

- `monaco-instruction-selection-v4`. 설계는 [운영 문서](../operations/monaco-instruction-selection.ko.md),
  결정은 [C40](../decisions.md).
- 문제: oracle 문서가 있고 시간 비의존이며 문서 4만 글자 이하인 pool 540개에서 seed 0으로 20문제(단일 답 10, 목록 10).
- 후보: naive(지시 없음)와 sonnet-high가 질문만 보고 쓴 analogical·clarify·local_check. 20/20 생성 성공.
- 선택: haiku-medium·luna-medium·flash-lite-high가 후보마다 3회 probe(문제당 36회). luna-low가 문제당 한 번 probe 답의
  항목을 묶고, 후보 점수는 9개 답 중 가장 중심인 답의 평균 항목 F1이다. 동점은 seed 0 무작위.
- 평가: 선택과 별도로 haiku-medium이 후보마다 3회 새로 풀고(240회), 공개 judge prompt로 luna-low가 채점한다.
  문제 동일 가중, paired bootstrap 95% CI.
- 재채점(v5 judge): 같은 실행 240회를 luna-high가 다시 채점했다. judge에는 응답 원문 대신 파싱한 최종 답을
  `ANSWER: [...]` 한 줄로 넘긴다(파싱 실패 응답만 원문). 아래 "judge가 본문 항목을 셌다" 참고.
- 실험 디렉터리 `outputs/experiments/2026-10-14_monaco-instruction-selection`,
  재채점 `outputs/experiments/2026-10-14_monaco-instruction-selection-rejudge`.

  아니다. 사후 최고는 후보 4개 중 실행 점수가 가장 좋게 나온 쪽을 고르므로 후보가 모두 같아도 양수가 된다.
  문제마다 실행 점수 12개를 후보 구분 없이 섞어 4묶음으로 나누면(2000회) 이 차이가 평균 +0.061

  다만 아래 probe 채점에서, 실행과 별개인 probe 점수로 후보를 고르면 실행에서 +0.084(CI 0.007–0.184)를 얻는다.
  선택과 평가 표본이 분리된 값이므로 후보 간 실제 차이는 있다고 본다.
- 고정 후보 중에서는 clarify가 가장 높다(naive 대비 +0.065, CI −0.014–0.172). 사후에 본 결과다.
- 단일 답 10문제에서는 selected가 best_in_hindsight와 같았고(0.796), 목록 10문제에서는 naive보다 낮았다.
  문제 수가 적어 CI가 넓다.
- 7문제(724, 826, 876, 1047, 1341, 1435, 1506)는 후보 간 실행 점수 차가 없다.
- 같은 문제 안의 후보 쌍 120개(원래 judge)에서 합의 순서와 실행 점수 순서가 같은 쌍 32, 반대 26, 어느 쪽이든 동점 62다.
- 동점: 단독 최고 10문제, 2·3·4개 동점 3·1·6문제. 규칙 정규화 완전 일치 합의였다면 20문제 중 14문제에서 같은 후보를 골랐다.

### probe 답 채점 (분석 전용)

probe 답 720개를 실행과 같은 judge(luna-high, 최종 답 줄)로 채점했다
(`outputs/experiments/2026-10-14_monaco-instruction-selection-probe-judge`, `scripts/judge_monaco_probes.py`).
gold를 쓰므로 선택 규칙이 아니라, 합의가 실패한 단계를 나누는 진단이다.

| 같은 문제 안 후보 쌍 120개 | 순서 같음 | 반대 | 동점 |
|---|---:|---:|---:|
| 합의 vs probe 점수 | 28 | 33 | 59 |
| probe 점수 vs 실행 점수 | 37 | 19 | 64 |
| haiku probe 점수 vs 실행 점수 | 34 | 15 | 71 |
| 합의 vs 실행 점수 | 31 | 22 | 67 |

| 정책 (실행 점수) | 평균 | naive 대비 (CI) |
|---|---:|---:|
| selected (합의) | 0.671 | −0.009 (−0.159–0.123) |
| probe_oracle (probe 점수 최고 후보, 동점 평균) | 0.764 | +0.084 (0.007–0.184) |
| best_in_hindsight | 0.784 | +0.104 (0.012–0.210) |

- **합의는 probe 답의 정답 여부를 가리키지 못한다.** 같은 문제 안에서 합의가 높은 후보의 probe 점수가 오히려 낮은
  쌍이 더 많다(28 대 33).
- **probe 정답은 실행으로 이어진다.** probe 점수로 고르면 실행에서 사후 최고의 약 80%(+0.084/+0.104)를 얻는다.
  실패 지점은 probe와 실행 사이가 아니라 합의 신호다.
- 합의 0.9 이상이면서 probe 점수 0.5 미만인 후보는 443의 analogical·local_check 두 개다(모두 빈 답).
  282 local_check는 합의 1.0, probe 점수 0.50으로 naive(0.75)보다 낮았다.
- 채점 결함 하나: 목록 judge가 gold보다 많은 겹친 항목을 내면 recall이 1을 넘었다. 공개 목록 judgement 9,440건에는
  없다. v6에서 recall을 1로 제한했고, 기록된 judgement는 그대로 두고 저장된 judge 응답으로 영향을 다시 계산했다.
  - 재채점 실행(위 주 결과): 0건, 변화 없음.
  - 원래 judge 실행: 116 naive·clarify 각 1회(1.2 → 1.0). 항상 naive·항상 clarify 평균이 각각 0.0033 낮아진다.
  - probe: 116 analogical 1회(1.2 → 1.0), 1237 naive 1회(recall 20/19, 점수 1.0 → 0.976). 116은 analogical이
    naive·clarify와 probe 점수 동점이 되어 probe 정답 점수로 고른 결과가 0.764에서 0.763(naive 대비 +0.083)이 된다.
    순서 일치 집계(같음/반대/동점)는 합의 vs probe 점수 28/33/59 → 28/31/61, probe 점수 vs 실행 37/19/64 → 36/19/65로
    바뀌고 해석은 같다.

### 확인한 문제

1. **빈 답끼리의 합의.** 443("dire wolf를 받은 인물")의 oracle 문서는 출연진 표뿐이고 dire wolf 언급이 없다.
   analogical 지시문의 "answer only from what the documents support"에 따라 probe 9개가 모두 `ANSWER: []`을 냈고,
   빈 답끼리 F1 1이라 합의 1.0으로 선택됐다. 실행 3회도 모두 빈 답으로 0점이었다. naive는 실행 3회 모두 1점이다.
   MoNaCo gold에 빈 답은 없다. probe의 빈 답은 37개로 443·444·1506·1809에 몰려 있다.
   - 사후 확인(결과를 본 뒤 계산, 선택 규칙으로 쓸 수 없음): 빈 답을 실패 slot으로 보면 443만 naive로 바뀌고,
     tie_average가 0.663에서 0.697이 된다.
2. **합의가 낮은 후보가 실제로는 가장 좋은 경우.** 444(요리별 허브)에서 clarify는 합의가 가장 낮았지만(0.34) 실행
   점수는 0.82로 다른 후보(0.09–0.17)보다 훨씬 높았다. clarify가 요리별로 나눈 답을 이끌어 답 형태가 갈렸다.
3. **행 안의 목록을 파서가 거부했다.** probe 형식 실패 36개 중 34개가 `["Homelander", ["Superman", ...]]`처럼 행 안에
   목록(빈 목록 포함)을 넣은 답이다. 471("The Seven 각각의 원작 대응 인물") 18개, 1720("중부 유럽 국가별 국민 음식") 13개,
   444 3개 등이다. 형식 계약은 행을 문자열 목록으로만 정했으므로 규칙대로 실패 slot(합의 0)으로 셌다.
   - 사후 민감도: 중첩·빈 목록을 허용해 바뀌는 3문제를 다시 묶었다
     (`outputs/experiments/2026-10-14_monaco-instruction-selection-nested-row-sensitivity`, $0.005).
     471은 analogical → local_check, 1720·444는 같은 선택이다. 471의 두 후보 실행 점수가 모두 0.52라 selected 점수는
     바뀌지 않는다.
   - 이 재묶기에서 1720(서로 다른 항목 122개)은 묶기 응답이 id를 정확히 한 번씩 나누지 못해 세 번째 호출(시도 5번째)에서
     성공했다. 본 실행에서는 471(55개)이 호출 안 재시도로 성공했고, 최대 99개(294)는 한 번에 성공했다.
4. **judge 검증 차이.** 1809(yes/no)에서 GPT-4o가 근거 이름만 낸 답("Answers: Chris Cornell")을 공개 GPT-4.1 judge는
   0점, luna-low는 1점으로 채점했다. 나머지 3건은 0.005–0.035의 수치 차이다.
5. **judge가 응답 본문의 항목을 셌다(원래 judge).** 목록 judge prompt는 "final answer length"를 응답 전체에 나온 답의
   수로 세라고 한다. 우리 실행 응답(평균 1,464자)에는 근거와 `Excluded` 절이 있어, luna-low가 제외한 항목까지 답 수나
   겹친 답으로 셌다. 952는 실행 12회의 최종 답이 모두 같았는데(두 작품) 점수가 0.31–0.67로 갈렸다. judge 검증에 쓴
   공개 GPT-4o 답은 평균 588자 자유 문장이라 이 경우를 덮지 못했다.
   - 재채점에서 같은 최종 답 묶음 27개(judge 183회)의 점수 범위는 평균 0.133에서 0.002로 줄었다. 952는 12회 모두 0.67이다.
   - 재채점으로 바뀐 점수는 240개 중 67개(평균 절대 차이 0.045)지만 정책 순서와 결론은 같다.
   - luna-high는 공개 GPT-4o 답 검증에서 14/20 일치로 luna-low(16/20)보다 낮았다. 공개 점수도 GPT-4.1의 판정이라
     어느 쪽이 맞는지는 확인하지 않았다.
6. **gold는 문제별로 검토하지 않았다.** 이전 점검에서 gold 결함 2건을 봤다. 5문제는 gold 행에 값이 여러 개다.

- 묶기 사전 확인: 이전 점검의 probe 답 72개에 v4 항목 묶기를 돌린 결과
  (`outputs/experiments/2026-10-14_monaco-item-clustering-check`, $0.0005), `Cholera`와 `Sixth cholera pandemic`,
  `Seventh cholera pandemic`을 다른 항목으로 두고 표기 차이만 있는 항목은 합쳤다. 다른 대상을 합친 예는 보지 못했다.
  910의 후보 점수는 0.53–0.60으로 갈렸다.

### 해석

- 이 20문제에서 cross-worker probe 합의로 고른 instruction은 naive나 무작위 선택보다 낫지 않았다.
- 후보 간 실제 차이는 있다. 사후 최고 − naive만으로는 잡음과 구분되지 않지만, 별도 표본인 probe 점수로 고르면
  실행에서 +0.084를 얻는다. 문제는 그 차이를 합의가 가리키지 못한다는 점이다(합의 vs probe 점수 28 대 33).
- 그 몇 문제에서 합의는 오히려 틀린 방향을 가리켰다(443 빈 답, 282 좁힌 해석, 444 가장 좋은 후보의 합의가 가장 낮음).
  합의는 정답 여부보다 해석의 일관성을 잰다. 범위를 좁히거나 거부를 유도하는 지시문일수록 답이 잘 일치한다.

### 남은 선택

- 빈 답을 실패 slot으로 보는 규칙은 결과를 본 뒤 나온 것이므로, 쓰려면 새 문제로 다시 확인해야 한다.
- 행 안 목록 허용은 형식 계약 변경(파서와 답 형식 문구)이다.
