# 발표용 보고서 작성 방식

이 가이드는 **발표용 보고서**에만 적용한다. 실행 기록·버전·운영 세부를 남기는 documentation용 보고서(예: 버전별 실행
보고서, 운영 문서)는 형식이 자유롭다.

발표용 보고서의 목적은 실험 내용 전달이다. 기록이 목적이 아니다. 기준 예시:

- [LongCoT Instruction Selection](2026-10-15-longcot-instruction-selection-summary.ko.md)
- [MoNaCo Instruction Selection](2026-10-15-monaco-instruction-selection-summary.ko.md)
- LongCoT Worker Selection 정리(2026-10-15)도 같은 틀을 따른다.

## 처음 읽는 사람 기준

- 이 보고서만 보고 처음 읽는 사람이 이해할 수 있게 쓴다. 다른 보고서를 참조해 설명을 대신하지 않는다.
- 실험 version, 후보 revision, 내부 결정 ID, 실행 디렉터리 같은 documentation 정보는 본문에 넣지 않는다.
  출처는 파일 끝 HTML 주석(`<!-- 자료: ... -->`)에 둔다.
- 결론을 이해하는 데 필요 없는 세부(단계별 비용, 보조 모델 이름, 동점 규칙 세부, 선택 분포, 재시도 규칙 등)는 뺀다.
- 용어는 정확히 쓴다. "낸 항목의 정답 비율"처럼 풀어 쓰기보다 precision·recall처럼 정해진 이름을 쓰고,
  같은 말이 두 뜻으로 읽히지 않게 한다(예: "단일 답 문제"와 "개별 답 평균"을 구분).
- 정책·지표는 한 줄로 뜻을 적는다(예: random = 무작위로 고를 때의 기대 점수, 평균 점수 = 목록은 F1·단일은 정답 1).

## 구조

| 절 | 담는 것 |
|---|---|
| Motivation | 전체 흐름과 잇는 큰 질문 한 줄, 그 아래 RQ1·RQ2. 가설은 RQ만으로 전달되지 않을 때만 한 줄 |
| Setup | 설계만. Benchmark(선정 이유 포함), 핵심 용어 정의, 조건·후보, 절차, 비교 정책, 지표. 주의사항·한계는 넣지 않는다 |
| Pre-pilot (있을 때) | 별도 절로 두고 제목에 돕는 RQ를 쓴다(예: "변형 후보 좁히기 (RQ2)"). 설정, 표, 결정을 함께 적는다 |
| Observation | 표마다 집계 방식을 캡션에 쓰고, 표 아래 bullet로 사실만 적는다. 필요한 곳에만 **분석**(직관적 설명)과 **예시**(실제 trace 하나)를 붙인다. RQ 밖의 추가 분석은 Observation 끝에 따로 둔다 |
| Conclusion | Motivation과 같은 문구의 RQ 제목 아래, 먼저 예/아니요로 답하고 근거 수치와 가설 지지 여부를 적는다. 곁가지 언급은 넣지 않는다 |
| 한계 | 설계상 제약, 그 설계를 택한 의도(예: test time에 쓸 수 있는 정보·신호만 사용), 그 결과의 실제 의미. 몇 개로 줄인다 |

## 문체와 내용

- 짧은 문장의 중첩 bullet. 한 bullet에 한 사실.
- 관련 실험은 Motivation·RQ·지표를 같은 틀로 맞춰, 나란히 볼 때 무엇이 다른지 드러나게 한다
  (예: instruction selection의 합의율 vs worker selection의 일관성, LongCoT vs MoNaCo 비교표).
- 지표는 RQ에 직접 답하는 것만 남긴다. 드물게만 정의되는 지표(예: 목록 문제의 완전 정답)는 뺀다.
- 표에는 읽는 데 필요한 열만 둔다. 다른 표와 중복되는 열, 같은 지표의 다른 계산 방식 열은 뺀다.
- 분석은 직관 한 줄 + 근거 수치 하나 + 예시 하나로 쓴다. 예시는 그 주장에 정확히 맞는지 원자료로 확인한다
  (예: "항목 빠뜨림" 예시가 실제로는 문서에 정답이 없는 경우가 아닌지).
- 조건 설명: 문제마다 달라지는 문구는 직관적인 가상 예시를 범주마다 하나 쓰고 공통 틀은 한 줄로 줄인다.
  고정된 짧은 prompt 변형은 실제 문구를 구체적으로 나열한다.
- 해석을 바꾸는 설계 세부는 Setup에서 쉬운 말로 풀어 쓴다(예: 이어 풀기를 조건과 무관하게 한 번만 했다면,
  조건 차이는 선택에서만 생긴다고 적는다).

## 수치와 기준선

- 선택(instruction·worker)을 평가하는 AUROC는 같은 문제 안에서 계산한다. 문제를 섞으면 난이도 효과가 들어간다.
  계산에 쓰인 문제 수를 표에 함께 쓴다.
- 사후 최고(best in hindsight)는 같은 반복 수로 잡음 기준선을 계산해 함께 보고, 선택 편향과 기준선을 bullet 하나로 적는다.
- 결과를 보고 정한 기준선(예: 가장 강한 worker 고정)은 실제 사용 시점에 알 수 없는 정보라는 점을 적는다.
- 선택에 쓴 probe 답을 재사용한 점수는 선택 편향이 있다고 적는다.
- 숫자는 원자료(targets, summary, trace)에서 다시 확인한다. 기존 보고서와 다르면 원자료 기준으로 고친다.
- 새로 계산한 수치는 스크립트와 결과를 `outputs/analysis/`(또는 manifest가 있는 `outputs/experiments/`)에 남긴다.
