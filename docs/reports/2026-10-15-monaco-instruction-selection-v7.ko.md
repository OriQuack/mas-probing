# MoNaCo instruction 합의 선택 v7: 층화 50문제

### 목적

oracle 설정(gold evidence 문서 + 질문)에서 instruction headroom(사후 최고 − naive)이 있는지, 합의 선택이 그것을
회수하는지 본다. v6까지의 결과(합의 선택 ≈ naive ≈ random, 사후 최고 ≈ 잡음 기준선)를 답 형식·대상·후보를 바꿔 다시
확인한다. 탐색 실험이다.

### 설정

- `monaco-instruction-selection-v7`. 설계의 정본은 [운영 문서](../operations/monaco-instruction-selection.ko.md),
  결정은 [C40](../decisions.md). v6과 다른 점:
  - 답 형식: 자유 서술 뒤 마지막 `Answers:` 줄. judge에는 이 줄만 넘긴다.
  - 합의용 항목: 문제당 `luna-low` 한 번으로 답 줄을 나누고(split), 항목이 줄의 연속 구간이며 나머지가 구분자뿐인지
    코드로 확인한다. 확인에 실패한 줄은 실패 slot이다. 그 뒤 기존 항목 묶기(cluster).
  - 대상: pool 540문제에서 공개 GPT-4o·Llama-3.1-405B oracle 점수 평균이 0이나 1인 문제를 빼고 층화한 50문제.
    목록 5구간(평균 점수 0.0–0.2 … 0.8–1.0) × 6, 단일 답은 한 모델만 맞힘 10·부분 점수 10. 층마다 seed 0.
  - 후보: naive, decompose(Least-to-Most), clarify(Metacognitive Prompting, 해석만), structured(Tab-CoT). 질문만 본
    작성·검토 subagent가 썼고 amendment 2를 50문제에 같이 적용했다
    (`outputs/analysis/2026-10-14_monaco-method-instruction-candidates/`).
- worker 3명 × 3회 probe로 선택, haiku-medium이 후보마다 3회 새로 실행, judge는 luna-high. 문제 동일 가중, paired
  bootstrap CI. sync, 동시 2. 2문제(459, 1018) sanity run(`...-v7-sanity-r2`, $0.25)을 통과한 뒤 본 실행.
- 실험 디렉터리 `outputs/experiments/2026-10-14_monaco-instruction-selection-v7`, 결과 `analysis/summary.json`.

  - 숫자 부분 점수 공식 `1 − |gold − pred| / max`를 공개 채점이 적용하지 않았다: 851, 904, 1438.
  - 134는 답 2(gold 15)인데 공개 채점이 0.87을 줬다.

### 주요 실패 유형

실행 600회의 손실(1 − 점수)은 50문제 합계 17.65점이다. 문제마다 주원인 하나를 수작업으로 붙여 나눴다. 한 문제에
원인이 섞이면(예: 1042는 범위 표기와 Antarctica "none") 주원인으로만 셌다.

| 유형 | 손실 비중 | 문제 |
|---|---:|---|
| 짧은 목록에서 항목 누락·오포함 | 31% | 72, 379, 1801, 1085, 1849, 1742, 459, 910, 1717, 640, 166 |
| 긴 목록(gold 20개 이상)에서 일부만 나열 | 28% | 1145, 913, 1042, 671, 1516, 1334, 101, 579, 726 |
| 문서에 근거가 없어 "none"·"문서에 없음"으로 답함 | 18% | 1053, 31, 421, 1196, 1683 |
| 단일 숫자 답의 수 세기 오류 | 10% | 1362, 134, 1438, 1293, 904 |
| 해석이 실행마다 흔들림 | 5% | 148 |
| gold·judge 형식 | 6% | 1018, 629, 1152, 1481, 60, 1784, 1670, 1341 |

- **목록 문제는 recall이 병목이다.** 목록 실행 360회의 precision은 0.78, recall은 0.48이다. 예측 항목 수는 gold의
  0.60배이고, 288회(80%)가 gold보다 적게 답했다. 많이 답한 경우는 23회다.
- **"none" 답은 oracle 문서가 불완전한 경우다.** 문서를 직접 확인했다.
  - 31: 문서에 Barkley의 팀 동료 이름이 없다.
  - 1053: 문서에 군주제 복원 시도에 대한 서술이 없다. 12회 모두 "none"이고 0점이다.
  - 1683: 문서에 175라는 수가 없다.
  - 1196: 문서는 Celine Dion의 출생지(Charlemagne)만 주고 가장 많이 팔린 캐나다 가수라는 연결 사실은 주지 않는다.
    naive는 "none", structured는 배경지식으로 맞혔다.

  모델이 문서 밖 지식을 쓰지 않으려 하고, gold는 문서 밖 지식을 요구한다.
- **수 세기 실패는 표·목록을 끝까지 세는 일에서 생긴다.** 72(에피소드 표에서 감독별 횟수), 1362(3 대 13), 134(8 대 15),
  1683(French 62 대 175)이 예다.
- **gold·judge 형식 문제.** 1018은 "99,550 to 130,000"처럼 범위로 답해 0점이었다. 629는 gold에 Italy가, 1152는 gold에
  DC와 ME-1이 들어 있다. 904는 같은 답 "26"을 judge가 실행마다 허용폭 안·밖으로 다르게 판정했다.

### 합의 선택이 목록 문제에서 naive보다 낮은 이유

1. **합의율이 점수를 예측하지 못한다.**
   - 같은 문제 안에서 후보 두 개씩 비교하면, 합의율이 높은 쪽의 점수가 높은 경우 48번, 낮은 경우 56번이다.
     recall(39 대 44)과 예측 항목 수(54 대 44)에도 관계가 없다.
   - 1위와 2위 후보의 합의율 차이는 중앙값 0.007이고, 30문제 중 24개가 0.05 미만이다.
   - 예: 459는 합의율 decompose 0.90, naive 0.89로 decompose를 골랐고 점수는 0.65에서 0.41이 됐다.
2. **사실상 무작위 선택인데 naive가 잘 뽑히지 않는다.**
   - 목록 30문제에서 naive는 4번 뽑혔다. 무작위면 7~8번이 기대값이다.
   - 목록에서는 naive 외 후보의 평균이 naive보다 낮다. 그래서 selected 0.543이 네 후보 평균 0.549와 거의 같다.
3. **일관되게 틀린 답이 높은 합의율을 받는다.** 1849의 structured는 합의율 0.78로 1위였지만 실행 답은 "Henry II" 하나였다.
   점수는 0.67에서 0.25로 떨어졌고, 이 한 문제가 목록 손실 −0.63점 중 −0.42점이다.

단일 답의 이득 +0.036도 대부분 1196 하나에서 나왔다. 3개 후보가 동점이었고 seed 무작위로 고른 clarify가 맞았다. 동점
후보 평균으로 계산한 기대 이득은 +0.21인데 실제로는 +0.67이었다.

### 사후 최고와 naive의 차이가 작은 이유

1. **관측된 차이 +0.054의 거의 전부를 잡음으로 설명할 수 있다**(기준선 +0.047).
2. **대부분의 문제에서 네 후보의 점수가 거의 같다.**
   - 문제별 후보 평균의 최대−최소는 중앙값 0.029이고, 26문제가 0.05 미만이다.
   - 25문제에서는 naive가 이미 최고점이거나 최고점과 동점이다.
   - 사후 최고의 이득 2.68점 중 1.88점(70%)이 5문제(1849, 1742, 1085, 1196, 148)에서 나온다. 최대−최소가 0.2 이상인
     문제는 10개다.
3. **주된 실패가 instruction으로 바뀌지 않는다.**
   - 문서에 없는 정보는 지시로 생기지 않는다.
   - 목록 수집·수 세기 실패는 네 후보에 비슷하게 나타난다. 목록 점수가 후보별로 0.53–0.57에 모여 있다.
   - 해석 차이로 갈리는 문제(148, 1849, 1742)는 소수다.
4. **단일 답은 천장에 가깝다.** naive가 0.79이다.

참고로 후보 간 분산은 0.0077이고 3회 평균에 섞인 실행 잡음 분산은 약 0.0033이다. 잡음보다 큰 후보 차이는 위의 10문제
정도에 몰려 있다.

### 결론

- v7에서도 합의 선택은 naive와 차이가 없다(+0.002). 목록에서는 무작위 선택처럼 움직였다.
- 사후 최고 headroom도 잡음 기준선과 구분되지 않는다. v6 50문제(+0.058 대 기준선 +0.045)와 같은 결론이다.
- 이 설정에서 손실의 약 87%는 해석이 아니라 다음 두 가지에서 나온다.
  - 문서에서 항목을 끝까지 모으고 세는 일(약 69%).
  - 문서 범위 밖의 gold(18%).

  둘 다 instruction 사이에 거의 차이가 없다.

### 후속 후보(미실행)

- split 확인 규칙을 완화해 101·1717 등을 다시 나누기(분석 전용, 실행 기록은 그대로).
- gold를 본 instruction 재작성이나 gold decomposition 제공으로 headroom 상한 확인.
- 잡음 기준선을 넘기 위한 실행 반복 수 증가. 단, 위 원인 구성상 효과 크기는 작을 것으로 본다.
