# 50f58759 — August 날짜 페이지의 Twitter/X 인용 수 (gold 3)

## 4.1 과제와 의도된 풀이

- 질문: "How many times was a Twitter/X post cited as a reference on the english Wikipedia pages for each day of August in the last June 2023 versions of the pages?"
- 의도(annotator): "the english Wikipedia pages for each day of August" = 날짜 문서 **"August 1" … "August 31"** 31개. 각 페이지의 "last edited version prior to July 2023"(= 2023-06-30 시점에 유효하던 판, 6월에 편집이 없었으면 그 이전 판)을 열어 Twitter 게시물 인용을 세고, **31개 페이지를 합산한 하나의 수** 3을 답한다.
- 실패 지점 후보: (1) "pages for each day of August"를 날짜 문서가 아니라 "영어 위키 전체에서 8월 각 날짜에 게시된 트윗"으로 오독, (2) "last June 2023 versions"를 "6월에 만들어진 마지막 판"으로 좁혀 6월 편집이 없는 페이지를 빼는 것, (3) 답을 31개 per-day 목록으로 내는 것(질문은 "How many times" → 단일 수).

## 4.4 Pre-execution preventability

- v6 draft(= s4 공유 draft)는 과제에서 명확히 도출되는 대상(“pages for each day of August” = August 1–31 문서)을 빼고 “의미를 규명하라, 데이터셋/덤프를 찾아라, feasibility를 판단하라”로 바꿨다. 과제에 충실한 지시라면 이 실패를 거의 확실히 막았을 것이다(v5가 같은 도구로 날짜 문서 접근이 가능함을 실증). → **YES-FAITHFUL**, confidence med-high.
- 추가로 과제 텍스트에서 도출 가능한 두 가지를 명시해야 한다: (a) 판 = 2023-06-30 23:59:59 UTC 이전의 최신 판(6월 편집이 없어도 그 판), (b) 답 = 31개 페이지 합계 한 개의 수. v5의 실패는 정확히 이 두 지점이었다 → v5는 **YES-TASKTEXT**, confidence med.
- 힌트에 정답 정보(어느 페이지에 트윗이 있는지, 3이라는 값)는 없다. API 사용법은 일반 지식이다.
- Base rate: 5개 run 모두 실패. A-equivalent(s4_A)는 draft의 오독 그대로 실패했으므로 노이즈가 아니다.
- 최소 수정(문장): “The pages are the 31 English Wikipedia date articles ‘August 1’ … ‘August 31’. For each, use the version current at the end of June 2023 (the latest revision on or before 2023-06-30 23:59:59 UTC, even if it was made before June). Count references citing an individual Twitter/X post and report the total over all 31 pages (with a per-page breakdown).”
