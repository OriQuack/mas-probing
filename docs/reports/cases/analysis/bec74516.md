# bec74516 — ORCID pre-2020 works 평균 (gold 26.4)

## 4.1 과제와 의도된 풀이

- 질문: 첨부 JSON-LD 파일에 ORCID가 있는 사람들의 ORCID 페이지에서 "pre-2020 works" 수의 평균.
- 파일(`bec74516...jsonld`, 직접 확인): ORCID `@id`가 있는 사람은 5명 — Manuela Nagel(author, 0000-0003-0396-0333), Tatjana Gavrilenko(0000-0002-2605-6569), John Bamberg(0000-0001-6102-7846), David Ellis(0000-0002-0209-2784), Peter Giovannini(0000-0002-1053-2030). Ehsan Dulloo, Prishnee Bissessur는 ID 없음.
- Gold: annotator 단계 "(54 + 61 + 1 + 16 + 0) / 5 = 26.4". 단, annotator는 "Counted the works from pre-2022"라고 적었고 질문은 pre-2020이다(gold 자체의 기준 불일치 가능성). 숫자는 GAIA 작성 시점(2023년경)의 ORCID 레코드 상태에 묶여 있다.
- 실패 지점 후보: (1) **시간 drift** — 2026년 현재 ORCID 레코드는 2023년과 다르다(뒤늦게 과거 논문이 연결됨). (2) ORCID 페이지는 JS 렌더링이라 `pub.orcid.org/v3.0/<id>/works` API XML을 읽어야 하는데, 25만~50만 자짜리 XML을 LLM page reader가 세면 부정확하다. (3) work group(중복 source 묶음) 단위 vs source record 단위.

### 체계적 오차 요약
1. **근본 원인: 라이브 ORCID 레코드(2026)는 gold가 만들어진 2023년 상태가 아니다.** 어떤 run도 archived snapshot(read_url의 date 인자)을 시도하지 않았다(grep 결과 `"date":"20..."` 사용 0회). ORCID 프로필은 JS SPA라 Wayback에서 쓸모 있는 snapshot이 있을지도 불확실하다.
2. **부차 원인: 긴 XML을 LLM reader로 세는 방식의 불안정성** — 같은 endpoint를 다시 읽으면 54/55/56/57, 60/64/65/66처럼 흔들리고, split part의 겹침을 합산하면 59 근처가 된다.
3. gold의 "pre-2022" 표기는 별개의 불확실성(질문은 pre-2020)이지만, Bamberg 1·Giovannini 0이 pre-2020과 맞는 점을 보면 annotator의 오기일 가능성이 있다. 확정 불가.

## 4.4 Pre-execution preventability

- 공유 d0 draft(v6)는 파일 읽기만 지시했고 과제에 충실했으며 모든 run에서 정확히 수행됐다. 실패는 d1 이후 집계와 데이터 시점에서 발생 → d0 수정 대상이 아님.
- 시간 drift를 d0에서 막으려면 "2023년경 상태의 ORCID 레코드를 archived snapshot으로 보라"는 지시가 필요한데, 과제 텍스트에는 시점이 없고(파일 datePublished 2022가 유일한 힌트), "pre-2020 works"는 표면상 시점 불변인 양이라 사전 검토자가 이를 알 근거가 없다(hindsight). 또한 ORCID SPA의 archived snapshot이 실제로 쓸 만한지도 불확실하다. → **NO**.
- 이중 집계(59 클러스터)를 막는 "split part를 합산하지 말고 group 총계와 대조하라"는 힌트도 d1 이후 실행 단계 문제이며, 고쳐도 ≈36으로 gold에 도달하지 못한다. → NO.
- Base rate: 5개 run 모두 실패, A-equivalent(s4_A)는 현재 데이터 기준으로 거의 정답(35.8)에 도달하고도 실패 → 노이즈가 아니라 데이터 시점 문제.
