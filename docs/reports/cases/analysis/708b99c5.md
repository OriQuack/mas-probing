# 708b99c5 — DeepFruits Connected Papers 그래프에서 가장 큰 bubble의 크기를 결정한 feature

## 4.1 과제와 의도된 풀이

- 질문: "On the DeepFruits fruit detection graph on Connected Papers from 2016, what feature caused the largest bubble to be the size it is?"
- Gold: `Citations`. Annotator는 그래프에서 가장 큰 bubble(Redmon 2015, YOLO)을 클릭하고 다른 bubble들과 feature를 비교했다. 그 결과 "Citations was the feature where the Redmon bubble exceeded all the others". `Citations`는 Connected Papers 논문 패널의 필드 이름이다. 그래프 legend 문구는 "Node size is the number of citations"다.
- 함정: (1) "feature"를 DeepFruits 시스템의 기술적 특징(RGB/NIR fusion 등)으로 오해하는 것. 이런 실수를 한 run은 없다. (2) 의미는 맞히고 표기만 다르게 쓰는 것(`Citation count`, `Number of citations`). GAIA scorer는 공백과 구두점만 제거한 뒤 문자열을 비교하므로 `citationcount`, `numberofcitations`는 `citations`와 다르다고 판정한다. scorer로 확인한 결과 `Citations`만 통과한다.

## 4.3 Cause codes

모든 실패 run에서 primary는 **S-SCORER**다. 의미가 같은 답(`Citation count` / `Number of citations` ≡ `Citations`)을 scorer가 거부했다. 2차 요인으로 O-FORMAT을 붙일 수 있다. 오케스트레이터 시스템 프롬프트의 "as few words as possible" 규칙을 엄격히 적용했다면 한 단어 `Citations`가 나왔을 수도 있다. 하지만 이것은 사후적 해석이다. "Citation count"는 GAIA 규칙을 어긴 답이 아니다.

**질문 1 답**: 실질 오류는 없다. Gold의 표기(Connected Papers 패널의 필드명 "Citations")와 답의 표기가 다를 뿐이므로 S-SCORER로 분류한다. 엄격한 GAIA 문자열 일치 기준에서 보면 표기 선택(O-FORMAT)이지만, 어떤 기준으로도 의미상 틀린 답은 아니다.

## 4.4 사전 예방 가능성

**질문 2 답(형식은 어디서 정해졌나)**: d0 지시는 표기를 정하지 않았다("Report a concise answer"). 워커 보고는 "citation count" 또는 legend 문구 "number of citations"를 썼다. 최종 표기는 **오케스트레이터 finish**가 정했다(v5 line 722, v6 line 847, A line 989, c2 line 896, c3 line 1296).

**질문 3 답(과제 텍스트에서 도출 가능한 d0 지시가 막았을까)**: 아니다.
- 과제 텍스트에는 "Citations"라는 필드명을 고를 근거가 없다. "feature"라는 단어만 있다. "Connected Papers가 쓰는 이름 그대로" 같은 지시를 주면 워커는 legend의 "number of citations"를 가져올 가능성이 크다. 실제로 v6의 답 `Number of citations`가 그렇게 나왔고, 오답이다. `Citations`는 그래프 패널 UI의 필드명이고, 이를 아는 것은 출처에 대한 사전 지식(hindsight에 가까움)이다.
- 최종 표기는 오케스트레이터가 정하므로, 워커용 지시가 finish의 단어 선택까지 통제하지는 못한다.
- 판정: 모든 run **NO**. 같은 draft를 쓴 A-equivalent run 4개(v6, A, c2, c3)가 전부 실패했지만, 원인은 scorer다.
